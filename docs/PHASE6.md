# Phase 6 notes: scheduling on GitHub Actions

New: `.github/workflows/daily.yml` and `ci.yml`, `.github/dependabot.yml`, `.pre-commit-config.yaml`,
`scripts/lock.sh`, `scripts/pin_actions.py`, `scripts/ci_run.sh`, `tests/test_workflows.py`,
`tests/test_pin_actions.py`, root `README.md`.
Changed: `requirements.txt` and `requirements-dev.txt` are generated from `requirements.in` / `requirements-dev.in`
(ranges, for local work). The hashed `requirements.txt` and `requirements-dev.txt` that the workflows install
are GENERATED by `scripts/lock.sh`. Install locally from the locked `.txt` files (see section 4.2 of the complete guide),
not from the `.in` files.

## Two things you must do before the first run

1. Lock the dependencies (hashes can only be produced with network access). Any Python 3.12+ with bash works:

       scripts/lock.sh        # bash (macOS, Linux, or WSL on Windows). Commit requirements.txt + requirements-dev.txt

2. Pin the actions to commit SHAs (doc 08). The workflows contain `actions/...@UNPINNED # v4` placeholders
   because I could not look up verified SHAs, and a guessed SHA is worse than none:

       python scripts/pin_actions.py     # needs git and network; rewrites to @<sha> # v4
       python scripts/pin_actions.py --check

   The versions in the comments (checkout v4, setup-python v5, upload-artifact v4) are majors I know exist. If newer
   majors exist, edit the comment first (for example `# v5`) and run the script. Dependabot will keep them current.

`tests/test_workflows.py::test_every_action_is_pinned_to_a_commit_sha` fails until step 2 is done, on purpose.

## What the workflow does

- Triggers: cron `7 3 * * *` and `7 13 * * *` (06:07 and 16:07 EAT) and manual `workflow_dispatch` with
  mode (normal, no-notify, dry-run) and optional sources.
- `permissions: contents: read`, one concurrency group (runs queue, never overlap), 15 minute job limit,
  12 minute limit on the run step, checkout without persisted credentials.
- Installs with `pip install --require-hashes --no-deps`, so an unhashed or tampered package fails the run.
- Secrets reach only three steps (Run, Alert, Ping) through `env`, never `with` or `run`. Dispatch inputs reach
  the shell only as environment variables and are validated in `scripts/ci_run.sh`.
- On failure: unsaved results are uploaded as a 7-day artifact, and a Telegram alert with the run link is sent.
  The alert step is self-contained (curl only), so it still works if checkout or install was what failed, and
  the bot token goes to curl on stdin, not the command line.
- On success: pings HEALTHCHECK_URL if set.

## Verification (doc 10)

1. Run workflow, mode `dry-run`: expect green, digest preview in the log, nothing saved or sent.
2. Mode `no-notify`: rows appear in the Sheet, no Telegram message.
3. Mode `normal`: digest arrives. Run again: no repeat messages.
4. Test the failure path: run with sources `bogus`. The run fails with exit 2, you get the Telegram alert.
5. Wait for three consecutive scheduled runs (about 06:07 and 16:07 EAT). Expected result: digests with no laptop.

## Healthchecks.io (dead-man's switch)

Create a check with period 1 day and grace 3 hours, store its ping URL as HEALTHCHECK_URL. It alerts if
no successful run pings within about 27 hours. (Per-run tracking arrives with Phase 7's three-strikes alert.)

## Decisions to confirm

1. Cron minute offset (:07). Doc 09/D5 says 03:00 and 13:00 UTC, but runs scheduled exactly on the hour are the ones GitHub
   delays most, and the success target is a digest before 07:00 EAT. Change the minute in daily.yml if you prefer :00.
2. `ruff` ignores E501 (the formatter owns line length) and the tests ignore the bandit `S` rules.
3. Only the Telegram alert is sent on failure. GitHub also emails the person who last edited the workflow's cron.
4. Free minutes: two runs a day at roughly 2 to 4 minutes each, about 120 to 240 minutes a month. Check GitHub's current
   free allowance for private repositories (doc 09 marks this "verify").
5. Scheduled workflows run only from the default branch, and secrets are not given to fork pull requests or Dependabot.
   CI needs none. Public repositories can have schedules disabled after 60 days of inactivity, so keep this one private.
6. pre-commit uses tags (gitleaks v8.18.4, ruff v0.5.0). Run `pre-commit autoupdate --freeze` to move them to SHAs.

Not in this phase: three-strikes alerting, retention cleanup, `sources check` (Phase 7).
